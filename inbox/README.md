# inbox/ —— 投稿区（无需本地构建）

**你不需要安装任何东西，也不需要会构建。** 把内容写成 Markdown、填好一份索引文件，放进这个目录，剩下的交给维护者。

这个目录存在的唯一目的，是**把「写内容」和「构建上线」彻底拆开**：写作的人只管写，构建的人顺带构建。

---

## 为什么会有这个目录

本站的技术栈是 MkDocs + Material 主题，构建一次全站约 **850 秒**，还要严格锁定 `mkdocs==1.6.1` + `mkdocs-material==9.7.7` 才能保证产物与线上逐字一致——版本稍有偏差，页眉、`meta generator`、导航结构就会变形。

这套流程对**维护者**是必要的，对**作者**却是纯粹的负担。于是本站把两者分开：

| | 传统方式 | 投稿区方式 |
|---|---|---|
| 安装 Python / MkDocs | 必须 | **不需要** |
| 学 `mkdocs.yml` 导航语法 | 必须 | **不需要** |
| 本地 `mkdocs serve` 预览 | 必须 | **不需要** |
| 懂 Git 分支与 PR | 建议会 | 网页上传即可 |
| 构建 850 秒 | 自己跑 | **维护者顺带跑** |
| 你实际要做的 | 全都要 | **写 md + 填 json** |

> **一句话**：复杂构建和装配依赖，交给有环境、有经验的人；你只负责把内容写好。

## 你要做的只有两件事

### 第一步：建一个投稿文件夹

在 `inbox/` 下新建一个文件夹，**文件夹名就是你的投稿 id**：

```
inbox/
└── my-first-article/        ← 你的投稿 id（小写字母、数字、连字符）
    ├── index.json           ← 索引文件，必填
    └── index.md             ← 你的正文，必填
```

id 命名规则：**只能用小写字母、数字和连字符 `-`**，例如 `mindustry-server-guide`、`json-tips-01`。不要用中文、空格、下划线或大写字母。

> 想省事？直接复制 `inbox/_template/` 整个文件夹，重命名成你的 id 再改内容即可。

### 第二步：填好索引文件 `index.json`

```json
{
  "schema_version": "1.0",
  "id": "my-first-article",
  "title": "我的第一篇投稿",
  "author": "你的昵称",
  "date": "2026-10-06",
  "summary": "一句话说明这篇写了什么，会显示在列表和搜索摘要里。",
  "target": "wiki",
  "nav": ["Wiki", "社区投稿", "我的第一篇投稿"],
  "tags": ["教程", "入门"],
  "files": ["index.md"],
  "assets": [],
  "license": "CC BY-SA 4.0",
  "status": "ready",
  "notes": "给维护者的补充说明，没有可留空字符串。"
}
```

**没有正文的 md 也照样能投稿**——索引文件本身就是给维护者看的装配说明书。

## 索引文件字段规范

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `schema_version` | 是 | 字符串 | 固定填 `"1.0"`，供工具判断格式版本 |
| `id` | 是 | 字符串 | **必须与文件夹名完全一致**；小写字母、数字、连字符 |
| `title` | 是 | 字符串 | 页面标题，会成为正文的 `#` 一级标题 |
| `author` | 是 | 字符串 | 署名，会写进页面与致谢列表 |
| `date` | 是 | 字符串 | 投稿日期，格式严格为 `YYYY-MM-DD` |
| `summary` | 是 | 字符串 | 一句话摘要，建议 40 字以内，不要换行 |
| `target` | 是 | 字符串 | 目标板块路径，取值见下方「target 取值」 |
| `nav` | 否 | 字符串数组 | **你期望的导航位置**，维护者据此登记 `mkdocs.yml`；不填则由维护者决定 |
| `tags` | 否 | 字符串数组 | 标签，用于归类与检索 |
| `files` | 是 | 字符串数组 | 随投稿的正文文件，**必须包含 `index.md`** |
| `assets` | 否 | 字符串数组 | 随投稿的图片等资源，相对投稿文件夹的路径 |
| `license` | 否 | 字符串 | 许可声明，默认 `"CC BY-SA 4.0"`（与本站一致） |
| `status` | 是 | 字符串 | `draft`（草稿，暂不装配）/ `ready`（可装配）/ `done`（维护者已装配） |
| `notes` | 否 | 字符串 | 给维护者的补充说明，例如特殊排版要求 |

### target 取值

`target` 决定内容最终落到站点的哪个板块，只能是下面这些前缀：

| target | 落点 | 适合什么内容 |
|---|---|---|
| `wiki` | `docs/wiki/` | 条目式技术知识、操作备忘、配置要点（**最常用**） |
| `wiki/community` | `docs/wiki/community/` | 成员经验分享、教程、踩坑记录 |
| `dev` | `docs/dev/` | 参与共建的流程与规范 |
| `faq` | `docs/faq/` | 问答式排障内容 |
| `about` | `docs/about/` | 站点自身的说明 |

不确定选哪个？**填 `wiki` 就行**，维护者装配时会帮你归到最合适的位置，并在 `notes` 里说明。

## 正文写作要求

正文就是普通的 Markdown，按 [Markdown 写作规范](https://docs.66131466.xyz/dev/writing/) 写即可。三条最要紧的：

1. **只用一个 `#` 一级标题**，章节用 `##`、小节用 `###`，不要跳级
2. **不要在 md 里写 YAML front matter**（开头那对 `---`）——本站未启用 `meta` 扩展，写了会当正文原样显示出来。元数据**只写在 `index.json`** 里
3. **图片用相对路径引用**，并把文件一起放进投稿文件夹：

   ```
   inbox/my-first-article/
   ├── index.json
   ├── index.md
   └── images/
       └── step-1.png        ← 正文里写 ![第一步](images/step-1.png)
   ```

   维护者装配时会连同 `images/` 一起搬到 `docs/` 下，相对路径保持不变，不用你改。

> 提示：正文里**不要写站内绝对路径**（如 `/dev/writing/`）。装配后目录层级会变，相对路径由维护者统一校正。

## 投稿前自检

- [ ] 文件夹名与 `index.json` 里的 `id` **完全一致**，且只用小写字母、数字、连字符
- [ ] `index.json` 是**合法 JSON**（可到 <https://jsonlint.com> 粘贴校验，注意别多写逗号）
- [ ] `date` 是 `YYYY-MM-DD` 格式
- [ ] `files` 里列出了所有正文文件，且**包含 `index.md`**
- [ ] 正文只有一个 `#` 一级标题，没有 YAML front matter
- [ ] 图片都在投稿文件夹内，且用相对路径引用
- [ ] `status` 已改为 `ready`（否则维护者会当草稿跳过）

## 怎么提交

三种方式任选，**都不需要本地环境**：

| 方式 | 操作 | 适合 |
|---|---|---|
| **网页上传**（推荐） | 在 GitHub 上打开 `inbox/`，点 **Add file → Upload files**，把整个文件夹拖进去，提交时选「新建分支并发起 PR」 | 所有人 |
| **Pull Request** | 会 Git 的话照常 fork → 提交 → PR，只提交 `inbox/` 下的内容即可 | 熟悉 Git 的人 |
| **Issue 附件** | 把 `index.json` 与 md 内容贴在 [Issue](https://github.com/eoccc/eoccc.github.io/issues) 里 | 完全不想碰 Git 的人 |

**你不需要**：跑构建、改 `mkdocs.yml`、碰 `docs/` 目录、更新 `data/site-info.json`、生成 sitemap。这些全是维护者的活。

## 维护者会做什么

收到投稿后，维护者执行「顺带装配」流程（下一位创作者构建时一并完成）：

1. 校验投稿：`python3 tools/apply_inbox.py --check`
2. 装配到站点源：`python3 tools/apply_inbox.py --apply`
3. 按 `nav` 字段在 `mkdocs.yml` 登记导航
4. 更新 `data/site-info.json` 的版本与日期
5. 构建全站（约 850 秒）并落地产物
6. 重新生成 sitemap，提交推送

装配完成后，投稿文件夹里的 `status` 会被标记为 `done`，并附上实际落点路径。

## 常见问题

**不会写 JSON，怕格式错？**
复制 `inbox/_template/index.json` 改字段值就行，别动结构。提交后维护者也会跑校验，格式有问题会在 PR 里指出，不会直接拒收。

**只有想法、没有正文，能投稿吗？**
可以。填好 `index.json` 并把 `files` 留成 `[]`（或只放一个空 `index.md`），说明你想写什么，维护者会帮你判断放在哪、需要什么格式。

**投稿后多久上线？**
取决于维护者的构建排期——本站构建一次 850 秒且需要锁定版本的环境，所以是**攒够一批一起构建**，不保证即时。急件请在 `notes` 里写明。

**能投稿代码/配置文件吗？**
可以，用代码块包起来并标注语言（如 ` ```json `）。代码块内的内容**保持原样不翻译**，这是本站的既定规则。

**我的稿子被装配后，`inbox/` 里的文件还在吗？**
在。投稿区保留原始投稿与索引，作为归档与追溯依据，也方便后续修订时对照。
