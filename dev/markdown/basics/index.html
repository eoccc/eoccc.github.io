    基础语法

    本页讲解日常写作最常用的 Markdown 语法。所有示例都给出「写法」与「效果」的对照。

    标题

    用 # 的数量表示标题层级，最多六级。# 与文字之间必须有一个空格。

    # 一级标题
## 二级标题
### 三级标题
#### 四级标题
##### 五级标题
###### 六级标题

    没有空格不会生效：

    #错误写法     ← 会被当成普通文字
# 正确写法

    层级使用原则

    规则 说明
    每页只有一个一级标题 即页面标题，通常由正文首个 # 提供
    层级不跳级 不要从 ## 直接跳到 ####
    层级用于结构，不用于字号 想放大文字应该用强调，而不是选高级标题

    另一种写法：下划线式

    一级和二级标题还可以这样写，但本站统一用 # 形式：

    一级标题
========

二级标题
--------

    段落

    段落之间用一个空行分隔。这是 Markdown 最容易被忽略、也最容易出错的规则。

    这是第一段。

这是第二段。

    没有空行会被合并：

    这是第一行。
这是第二行。

    上面两行会渲染成同一段：「这是第一行。这是第二行。」——因为它们之间没有空行。

    想让两行属于同一段但强制换行，可在行尾加两个空格，或直接插入 <br>。但本站更推荐拆成两个段落，语义更清晰。

    强调

    写法 效果 说明
    *斜体* 斜体 用单星号
    _斜体_ 斜体 用单下划线，等价
    **粗体** 粗体 用双星号
    __粗体__ 粗体 用双下划线，等价
    ***粗斜体*** 粗斜体 三个星号叠加

    推荐统一使用星号形式（* / **），避免下划线在词中出现时被误判：

    snake_case_name      ← 下划线不会触发斜体，因为它在词中间
_snake_case_name_    ← 这样才触发斜体

    本站不支持删除线

    ~~删除线~~      ← 原样显示，不会变成删除线

    如需表达「已废弃」，直接用文字说明，例如「（已废弃）」。

    列表

    无序列表

    用 -、*、+ 均可，本站统一用 -。

    - 第一项
- 第二项
- 第三项

    建议在符号与文字之间留一个空格，兼容性最好。

    有序列表

    用「数字 + 点」：

    1. 第一步
2. 第二步
3. 第三步

    数字不必连续，渲染时会自动重新编号：

    1. 第一项
1. 第二项      ← 写 1 也会渲染成 2
1. 第三项

    嵌套列表

    子项需要缩进（推荐 2 或 4 个空格），缩进量必须一致：

    - 父项
  - 子项
  - 子项
- 另一个父项
  - 子项
    - 孙项

    缩进不一致会导致层级错乱，详见细节与常见错误。

    列表中的多段内容

    列表项内要放多个段落，后续段落需缩进对齐：

    - 第一段内容

  第二段内容，缩进两个空格

    本站不支持任务列表

    - [ ] 待办
- [x] 已完成      ← 原样显示，不会变成复选框

    需要表达完成状态时，用文字或表格：

    | 事项 | 状态 |
|---|---|
| 撰写初稿 | 已完成 |
| 补充示例 | 进行中 |

    链接

    基本写法

    [链接文字](https://example.com)
[链接文字](https://example.com "鼠标悬停提示")

    站内链接

    指向本站其他页面，用相对路径：

    [基础语法](basics.md)           ← 同目录
[写作规范](../writing.md)        ← 上一级目录
[首页](../../index.md)           ← 上两级

    指向目录时以 / 结尾，mkdocs 会自动映射到 index.md：

    [编程语言](../../wiki/langs/)    ← 对应 wiki/langs/index.md

    路径写错的链接不会报错，只会变成 404。发布前建议逐个点开确认。

    锚点链接

    跳转到本页或他页的某个标题：

    [回到标题](#标题)                          ← 本页
[看细节](../../dev/markdown/pitfalls.md#表格)  ← 他页

    锚点由标题生成：转小写、空格换连字符、去掉标点。中文标题保留原字：

    标题 锚点
    ## 基础语法 #基础语法
    ## 常见错误 #常见错误
    ## 1. 第一个 #1-第一个

    本站不支持裸链接自动转换

    https://example.com      ← 原样显示为纯文本，不是可点击链接

    必须写成 [https://example.com](https://example.com) 或尖括号形式：

    <https://example.com>

    图片

    基本写法

    ![替代文字](图片路径)
![替代文字](图片路径 "悬停提示")

    替代文字（alt）不可省略——图片加载失败时它会显示，也用于无障碍阅读。

    站内图片的相对路径

    Markdown 图片的路径相对于当前源文件所在目录解析。而页面渲染后会多一级目录（NAME.md → NAME/index.html），因此相对路径容易失效。

    本站的做法是统一使用站点绝对路径：

    <img src="/wiki/langs/assets/json-structure.svg" alt="JSON 结构示意">

    即从站点根开始写完整路径，与页面所在层级无关，最不易出错。

    为什么不用 ![](相对路径)：本地 Markdown 预览能显示，但构建后可能 404，且 mkdocs 会对本地图片做链接校验、缺失时报警告。详见本站渲染规则。

    图片与链接组合

    [![替代文字](图片路径)](跳转地址)

    点击图片即可跳转。

    引用

    用 > 表示引用块：

    > 这是一段引用。

    多行引用每行都要加 >：

    > 第一行
> 第二行

    嵌套引用叠加 >：

    > 外层
>
> > 内层

    引用块内可以放列表、代码等，用法与正文一致。

    本站未启用 admonition 扩展，因此 !!! note 之类的写法会原样显示为文本。需要醒目提示时，用引用块加粗体开头即可。

    分隔线

    用三个及以上 -、* 或 _ 单独成行：

    ---

    注意：--- 紧跟文字下方时，可能被解析成「标题」或「表格分隔符」，而不是分隔线。前后留空行可避免歧义：

    上一段内容

---

下一段内容

    行内代码

    用反引号包裹：

    使用 `git commit` 提交。

    内容含反引号时，用双反引号包裹：

    ``内容里有 ` 反引号``

    小结

    语法 写法 关键点
    标题 # 文字 # 后必须有空格
    段落 空行分隔 少空行会合并成一段
    强调 *斜* **粗** 统一用星号
    列表 - 项 缩进决定层级
    链接 [文](址) 站内用相对路径
    图片 <img src="/绝对路径"> 用站点绝对路径
    引用 > 文字 多行每行都要 >
    分隔线 --- 前后留空行
    行内代码 `代码` 反引号包裹
