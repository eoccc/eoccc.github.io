    本站渲染规则

    Markdown 本身只是一个基础规范，实际渲染效果取决于站点启用了哪些扩展。本页说明本站的真实支持情况，避免你写出「看起来对、渲染不出来」的语法。

    本站启用的扩展

    本站基于 MkDocs + Material 主题，实际启用的 Markdown 扩展如下：

    扩展 作用
    toc 生成标题锚点与目录
    tables 支持表格语法
    fenced_code 支持围栏式代码块
    md_in_html 允许在 HTML 块内使用 Markdown
    attr_list 支持给元素添加属性

    主题启用的特性：

    特性 作用
    navigation.tabs 顶部标签导航
    navigation.sections 侧边栏分组
    navigation.top 回到顶部按钮
    search.suggest 搜索建议
    content.code.copy 代码块复制按钮

    支持度总览

    语法 是否支持 说明
    标题 # ✅ 最多六级
    段落、空行 ✅
    强调 * ** ✅
    列表（有序/无序/嵌套） ✅
    链接、锚点 ✅
    图片 ✅ 建议用内联 <img>
    引用 > ✅
    分隔线 --- ✅
    行内代码 ✅
    表格 ✅ 需分隔行
    围栏代码块 + 高亮 ✅ 需标注语言
    语法高亮 ✅ 常见语言均支持
    复制按钮 ✅ 代码块自动带
    HTML 混排 ✅ 已启用 md_in_html
    属性列表 {: .cls } ✅ 已启用 attr_list
    自定义锚点 {#id} ✅ 已启用 attr_list
    标题目录 [TOC] ✅ 生成目录容器

    不支持的语法

    以下写法在本站不会生效，会原样显示为纯文本：

    语法 写法 表现
    删除线 ~~文字~~ 原样显示 ~~文字~~
    任务列表 - [ ] 待办 原样显示，无复选框
    脚注 文字[^1] 被当作链接处理，异常
    定义列表 术语 换行 : 定义 合并成普通段落
    上下标 H~2~O、x^2^ 原样显示
    高亮标记 ==文字== 原样显示
    admonition !!! note 原样显示为文本
    裸链接自动转换 https://a.com 纯文本，不可点击

    替代方案

    想要的效果 本站替代写法
    删除线 文字说明「（已废弃）」
    任务列表 用表格列「状态」
    脚注 用文末「相关阅读」或链接
    定义列表 用表格（术语 / 说明两列）
    上下标 用行内代码，如 H2O、x^2
    高亮 用粗体 **文字**
    醒目提示 用引用块 > + 粗体开头
    可点击链接 写完整 [文字](地址) 或 <地址>

    图片的路径规则

    为什么本站用内联 <img>

    Markdown 图片语法 ![](路径) 有两个问题：

    1. 路径相对源文件解析，而页面渲染后会多一级目录（NAME.md → NAME/index.html），相对路径容易失效
    2. mkdocs 会对本地图片做链接校验，缺失时产生构建警告

    因此本站统一用站点绝对路径的内联 <img>：

    <img src="/wiki/langs/assets/json-structure.svg" alt="JSON 结构示意">

    要点：

    要点 说明
    以 / 开头 表示站点根，与页面层级无关
    必须写 alt 图片加载失败时显示，也用于无障碍
    可用 width 控制尺寸 <img src="..." alt="..." width="400">
    路径基于仓库根 如 /ext/img/mindustry/...、/wiki/langs/assets/...

    什么时候可以用 Markdown 图片语法

    仅当图片与源文件同目录、且不介意构建警告时。本站不推荐，请统一用内联 <img>。

    代码块的高亮规则

    标注语言标识即可高亮，本站支持 Pygments 的全部常见语言：

    ```json
{"key": "value"}
```

    不标注语言时代码块仍会渲染，但没有高亮：

    ```
纯文本，无高亮
```

    推荐：始终标注语言；不确定时用 text。

    链接的解析规则

    链接类型 写法 解析方式
    站内相对 [文](../writing.md) 相对当前源文件
    站内目录 [文](../../wiki/langs/) 映射到该目录的 index.md
    站内绝对 [文](/dev/writing/) 从站点根解析
    站外 [文](https://a.com) 直接跳转
    锚点 [文](#标题) 本页内跳转

    注意：写错的链接不会报错，只会变成 404。发布前建议逐个确认。

    目录（TOC）

    页面右侧的目录由 toc 扩展自动生成，无需手动写。

    [TOC] 标记会插入一个目录容器，但本站页面已由主题提供目录，一般不需要使用。

    与写作规范的区别

    文档 讲什么
    本页 语法层面：哪些语法支持、哪些不支持
    Markdown 写作规范 风格层面：命名、用词、章节组织

    两者配合使用：先确认语法可用，再按规范组织内容。

    快速判断表

    写作时遇到不确定的语法，按此表判断：

    情况 处理
    基础语法（标题/列表/表格/代码） 直接用
    需要删除线、任务列表、脚注 不支持，换替代方案
    需要醒目提示框 用引用块 + 粗体
    需要插图片 用内联 <img src="/绝对路径">
    需要自定义样式 用 attr_list 加类名，但慎用
    需要 HTML 可以用，前后留空行

    小结

    • 本站启用了 toc / tables / fenced_code / md_in_html / attr_list 五个扩展
    • 不支持删除线、任务列表、脚注、定义列表、上下标、==高亮==、admonition
    • 图片统一用站点绝对路径的内联 <img>
    • 代码块必须标注语言才有高亮
    • 不确定时，优先用最基础的语法
