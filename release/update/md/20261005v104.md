# v1.0.4 · 文档站版本发布

`v1.0.4` · 正式发布 · 发布：2026-10-05 · 作者：AtomCode

本次更新把 Mindustry 中文板块的汉化补齐、新增「编程语言」分支（JSON / HJSON 深度讲解），
并完善了站点 SEO 与赞助说明。以下是 v1.0.3 → v1.0.4 期间的全部改动。

---

## 一、本版主要新内容

### 1. Mindustry 中文板块汉化补齐

「游戏内容」分支（`content/`）此前存在大量未汉化内容，主要是 WikiGen 自动生成的属性表格。
本次系统性补齐：

- **属性表格标签汉化**：125 种标签、4669 处，如 `Property/Value` → `属性/值`、
  `Health` → `生命值`、`Build Time` → `建造时间`、`Liquid Capacity` → `液体容量`
- **深层页面文案汉化**：650 种未译单元，覆盖 `Modding Classes`、`logic`、`servers`、
  `serverUiBuilder`、`datapatches` 等分支的表格备注列与散文段落
- **量级**：`content/` 分支改写 526/530 个文件（99.2%）、5851 行
- **覆盖率**：zh 810 个文档全部含中文，与英文原文逐字相同的未译单元仅剩 3 处
  （2 处为上游 WikiGen 生成的数据产物 `5.0null`，1 处为代码包名映射，
  按汉化规则均保留原文）

### 2. 新增「编程语言」分支（JSON / HJSON）

在 Wiki 下新增独立的编程语言分支，拆分为多个文档而非堆在单页：

| 页面 | 内容 |
|---|---|
| 总览 | 两者的关系（HJSON 是 JSON 的超集）、格式选择速查 |
| JSON 基础 | 语法结构、两种容器、六种数据类型、书写规则、常见错误、校验方法 |
| HJSON 基础 | 设计目标、相对 JSON 放宽的四个方面、必须遵守的规则、常见误区 |
| 两者对比 | 语法差异速查、逐项对照、选用建议、转换方式 |

配有三张原创 SVG 示意图：

- **集合关系图**：直观呈现 JSON ⊂ HJSON
- **结构示意**：左侧 JSON 源码、右侧解析后的结构树（含类型标注）
- **语法对照**：注释 / 键名引号 / 分隔逗号 / 多行字符串四组左右对照

### 3. 图片资源全量迁移

从上游仓库迁移全部 5180 个图片资源（含此前未被页面引用的约 4600 个素材），
`ext/img/mindustry` 共 5290 个文件，避免后续引用时缺图。

### 4. 修复更新日志页正文丢失

`release/update/` 页面的 `<article>` 正文曾被替换为占位符 `stub`，导致筛选栏、
日志容器与脚本引用全部缺失，页面无法查看任何更新详情。本次按最后完好版本还原。

### 5. 站内导航与侧边栏

- 新增「编程语言」可展开分组
- 新增「关于 → 自愿赞助」板块，明确赞助完全自愿、不换取特殊权限，
  资金用于域名 / CDN / 服务器 / 项目开发相关基础设施

### 6. SEO 与站点可见性

- 新增 sitemap 生成脚本，输出 `sitemap.xml` 与 `sitemap.txt`（含 changefreq / priority）
- 添加 `BingSiteAuth.xml`，完成 Bing 站点所有权验证
- 修复上游含字面 `%20` 的目录名编码问题（`Modding%2520Classes`），
  使 524 条 URL 可被正确收录

### 7. 开发者文档补充

- 新增「Sitemap 生成与维护」章节：构建方式、新增页面后的更新步骤
- 新增「.NET 8 SDK 安装」章节：微软官方源安装流程与环境记录

## 二、关于「小欧负担」问题

「小欧」（社区中承担日常事务统筹与协调的角色）长期面临一个现实矛盾：

**文档与站点的维护工作高度依赖少数人**。每一处汉化补齐、每一次结构更新，
都需要有人逐页核对；而随着 Mindustry Wiki 持续同步上游、社区内容不断增长，
单点承担的工作量会持续累积。

本次更新在以下方面减轻了这份负担：

- **汉化补齐从"逐页手工"变为"可复核"**：zh 与 en 双源已同步入库，
  任何未译内容都能通过对照扫描快速定位，不必再靠人工通读
- **新增内容不再堆在单页**：「编程语言」分支按主题拆分，
  后续增补只需改动对应文件，降低改错与互相影响的风险
- **sitemap 自动化**：新增页面后运行一条命令即可更新，
  无需手工维护 URL 列表
- **赞助说明明确化**：把"自愿、不影响使用、不换取权限"写进站点，
  减少因误解产生的沟通成本

这些改动不能消除负担，但能让维护工作更可交接、更少依赖个人记忆。
