# 细节与常见错误

本页汇总写作时最容易踩的坑。每一条都给出**错误写法 → 现象 → 正确写法**，便于对照排查。

## 一、空行问题

### 1.1 段落之间少了空行

```markdown
第一段内容。
第二段内容。
```

**现象**：两行被合并成一段，显示为「第一段内容。第二段内容。」

**原因**：Markdown 以空行划分段落，没有空行就属于同一段。

**正确写法**：

```markdown
第一段内容。

第二段内容。
```

### 1.2 列表前后少了空行

```markdown
下面是一些项目：
- 项目一
- 项目二
后面还有内容。
```

**现象**：列表可能被吞进段落，或「后面还有内容」被并入最后一个列表项。

**正确写法**：列表**前后各留一个空行**。

```markdown
下面是一些项目：

- 项目一
- 项目二

后面还有内容。
```

### 1.3 表格前少了空行

```markdown
说明文字：
| A | B |
|---|---|
| 1 | 2 |
```

**现象**：表格可能不渲染，或表头被并入段落。

**正确写法**：表格前留空行。

### 1.4 标题前少了空行

```markdown
上一段内容。
## 新章节
```

**现象**：某些解析器下 `## 新章节` 不会变成标题。

**正确写法**：标题前留空行。

### 空行速查

| 元素 | 前 | 后 |
|---|---|---|
| 标题 | 空行 | 空行 |
| 段落 | 空行 | 空行 |
| 列表 | 空行 | 空行 |
| 表格 | 空行 | 空行 |
| 代码块 | 空行 | 空行 |
| 引用 | 空行 | 空行 |

**一句话原则**：**块级元素之间，统统留空行。** 多留空行无害，少留一定出问题。

## 二、缩进问题

### 2.1 列表嵌套缩进不一致

```markdown
- 父项
  - 子项
   - 另一个子项      ← 缩进 3 空格，与其他不一致
```

**现象**：层级错乱，或子项变成普通段落。

**正确写法**：**同级缩进量必须完全相同**。本站推荐 2 或 4 个空格，**全篇统一**。

### 2.2 代码块缩进不足

```markdown
  code here      ← 只缩进 2 空格
```

**现象**：不会被识别为代码块，显示为普通段落。

**正确写法**：缩进式代码块需要**至少 4 个空格**。**本站推荐直接用围栏式**，不受缩进影响。

### 2.3 列表中的代码块缩进不对

````markdown
- 列表项

```json
{"a": 1}
```
````

**现象**：代码块脱离列表，层级断裂。

**正确写法**：代码块需缩进到与列表内容对齐：

````markdown
- 列表项

  ```json
  {"a": 1}
  ```
````

### 2.4 Tab 与空格混用

**现象**：缩进看起来一样，实际层级不同。

**正确写法**：**统一用空格**，不要用 Tab。编辑器建议设置为「Tab 转 2 或 4 空格」。

## 三、符号冲突

### 3.1 行首的符号被误判

```markdown
# 这不是标题，是井号开头
- 这不是列表
* 这也不是列表
```

**现象**：被当成标题 / 列表。

**正确写法**：转义或用行内代码包裹。

```markdown
\# 转义后正常显示
`# 用代码包裹也安全`
```

### 3.2 表格里的竖线

```markdown
| 运算符 | 说明 |
|---|---|
| | | 逻辑或 |
```

**现象**：列数错乱，表格破损。

**正确写法**：转义竖线 `\|`。

```markdown
| 运算符 | 说明 |
|---|---|
| `\|` | 逻辑或 |
```

### 3.3 下划线触发斜体

```markdown
变量名 snake_case_name 中的下划线      ← 安全，在词中间
_前后都有下划线_ 会被斜体              ← 触发斜体
```

**现象**：本该是普通文字的部分变成斜体。

**正确写法**：**强调统一用星号** `*` / `**`，把下划线留给标识符。

### 3.4 星号触发斜体

```markdown
计算 a * b * c 的结果
```

**现象**：`* b *` 之间的内容变成斜体。

**正确写法**：用行内代码 `` `a * b * c` ``，或转义 `\*`。

### 3.5 分隔线 vs 标题 vs 表格

```markdown
标题文字
---
```

**现象**：`---` 可能被解析为「二级标题」的下划线，而不是分隔线。

**正确写法**：分隔线**前后留空行**，且不要紧跟在文字下方。

```markdown
标题文字

---

下一段
```

### 3.6 代码块外的反引号不配对

```markdown
这是 `未闭合的行内代码
```

**现象**：反引号原样显示，或后续内容被意外包裹。

**正确写法**：**成对使用**。内容本身含反引号时，用双反引号包裹。

## 四、链接与图片

### 4.1 站内链接路径写错

```markdown
[基础语法](basics.md)                      ← 同目录，正确
[写作规范](writing.md)                     ← 少了几级，错误
[写作规范](../../../dev/writing.md)         ← 正确
```

**现象**：链接**不会报错**，点击后 404。

**正确写法**：确认相对层级。源文件位置决定路径：

| 当前文件 | 目标 | 正确写法 |
|---|---|---|
| `wiki/langs/markdown/basics.md` | 同目录的 `advanced.md` | `advanced.md` |
| `wiki/langs/markdown/basics.md` | `wiki/langs/json.md` | `../json.md` |
| `wiki/langs/markdown/basics.md` | `wiki/langs/index.md` | `../` |
| `wiki/langs/markdown/basics.md` | `dev/writing.md` | `../../../dev/writing.md` |

### 4.2 目录链接忘了结尾斜杠

```markdown
[编程语言](../)     ← 正确：映射到 index.md
[编程语言](..)      ← 可能无法映射到 index.md
```

### 4.3 图片路径用相对路径

```markdown
![](assets/pic.svg)
```

**现象**：本地预览正常，**构建后 404**。因为页面渲染后多一级目录。

**正确写法**：用站点绝对路径的内联 `<img>`。

```markdown
<img src="/wiki/langs/assets/pic.svg" alt="说明">
```

### 4.4 图片缺 alt

```markdown
<img src="/path/pic.svg">
```

**现象**：图片加载失败时无任何提示，无障碍阅读也受影响。

**正确写法**：**始终写 `alt`**。

### 4.5 锚点与标题不匹配

```markdown
## 常见错误

[看这里](#常见错误)      ← 正确
[看这里](#常见错误问题)   ← 错误，多字
```

**现象**：点击后不跳转或跳到页首。

**锚点生成规则**：

| 标题 | 锚点 |
|---|---|
| `## 常见错误` | `#常见错误` |
| `## 1. 第一个` | `#1-第一个` |
| `## 表格 vs 列表` | `#表格-vs-列表` |

**规律**：转小写、空格换连字符、去标点、中文保留。

## 五、不支持语法的误用

### 5.1 用删除线

```markdown
~~已废弃~~
```

**现象**：原样显示 `~~已废弃~~`。

**替代**：写「（已废弃）」。

### 5.2 用任务列表

```markdown
- [ ] 待办
```

**现象**：原样显示，没有复选框。

**替代**：用表格列「状态」。

### 5.3 用 admonition

```markdown
!!! note
    提示内容
```

**现象**：原样显示为文本，非常突兀。

**替代**：用引用块。

```markdown
> **注意**：这里是提示内容。
```

### 5.4 用裸链接

```markdown
https://example.com
```

**现象**：纯文本，不可点击。

**替代**：`[https://example.com](https://example.com)` 或 `<https://example.com>`。

### 5.5 用脚注

```markdown
文字[^1]

[^1]: 注释
```

**现象**：被当作链接处理，显示异常。

**替代**：用「相关阅读」小节或括号说明。

## 六、结构问题

### 6.1 跳级使用标题

```markdown
## 二级标题
#### 四级标题      ← 跳过了三级
```

**现象**：目录层级错乱，侧边栏显示异常。

**正确写法**：**逐级递进**，不要跳级。

### 6.2 一页多个一级标题

```markdown
# 页面标题
## 章节
# 另一个一级标题      ← 一页应只有一个 H1
```

**正确写法**：一页**只有一个 `#`**，即页面标题。

### 6.3 用标题调字号

```markdown
###### 我想让字小一点
```

**现象**：语义错误，且会进入目录。

**正确写法**：标题表达**结构层级**，不用于调整视觉大小。

### 6.4 手写目录

**现象**：手写目录需随内容更新，容易过期。

**正确写法**：本站目录**由主题自动生成**（右侧栏），无需手写。

## 七、快速排查表

| 现象 | 最可能的原因 | 检查点 |
|---|---|---|
| 两段文字粘在一起 | 少了空行 | 段落间加空行 |
| 表格不渲染 | 少了分隔行 / 少了空行 | 补 `|---|` 和空行 |
| 列表层级错乱 | 缩进不一致 | 统一缩进量 |
| 代码块没高亮 | 没标语言 | 加 `json` / `bash` 等 |
| 图片 404 | 用了相对路径 | 改站点绝对路径 |
| 链接 404 | 路径层级错 | 数清 `../` 层数 |
| 出现多余符号 | 符号未转义 | 加 `\` |
| 提示框没样式 | 用了 admonition | 改用引用块 |
| 复选框没出现 | 用了任务列表 | 改用表格 |
| 斜体乱出现 | 下划线/星号冲突 | 用行内代码包裹 |

## 八、写作检查清单

发布前逐项确认：

| 检查项 | 说明 |
|---|---|
| 块级元素前后有空行 | 标题、段落、列表、表格、代码块、引用 |
| 列表缩进全篇统一 | 统一 2 或 4 空格，不用 Tab |
| 标题逐级递进 | 只有一个 `#`，不跳级 |
| 表格格式正确 | 有分隔行、列数一致、竖线已转义 |
| 代码块标注语言 | 用 `json` / `bash` 等，不确定用 `text` |
| 图片路径正确 | 站点绝对路径 + 必写 `alt` |
| 站内链接层级正确 | 目录链接以 `/` 结尾 |
| 锚点与标题一致 | 转小写、空格换连字符 |
| 未使用不支持语法 | 删除线、任务列表、脚注、admonition |
| 代码块内容未翻译 | 仅 Mindustry 文档适用 |

> 本站**不支持任务列表**（`- [ ]`），所以上面的清单改用表格呈现——写成复选框的话，渲染后会原样显示为文本。

## 小结

绝大多数 Markdown 问题都源于三条规则：

1. **块级元素之间留空行**
2. **同级缩进必须一致**
3. **特殊符号该转义就转义**

把这三条记住，剩下的问题基本都能自行排查。
