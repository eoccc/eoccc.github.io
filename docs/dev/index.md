# 开发者文档

欢迎参与 Everyone Create Community（每个人创作社区）共建。本板块按参与方向分为两类，可按自己的角色直接进入对应路径。

## 贡献指南

### v1.0.4.2 重大更新：云端 CI 自动构建流水线

v1.0.4.2 引入 GitHub Actions 云端自动构建流水线，把「构建」从贡献者的电脑搬到了云端，因此本板块现在提供**两套并行的贡献方案**，你可以按自己的情况挑一条更顺手的路。

> **【重要声明 · 务必阅读】**
>
> 当前这套 CI 云端构建系统属于**预发布版本**，**系统不稳定，仍需要长期测试、反复迭代修改与校验实际输出内容，不保证输出结果完全无误**。现阶段依然**优先推荐本地构建方式**。用户可以自行修改、调试这套流水线相关配置用于测试。

**【云端自动构建】** 适合轻度贡献者——偶尔改几个错别字、补一段说明、修一个失效链接；也适合电脑上没有环境、装不上 Python、或不愿意为此折腾的成员，以及只想专注于写作、不想碰工具链的新手。你只需要在网页上编辑 Markdown 或 SVG、提交 PR，云端便会自动完成环境准备与构建校验：通过则显示绿色对勾，失败则显示红色叉号并指出报错位置，修正后重新提交即可。整个过程不需要安装任何东西。代价是受预发布状态影响，云端结果不保证完全可靠，偶尔可能出现环境差异导致的失败或输出偏差。

**【本地自构建】** 适合需要频繁改动、要调导航与主题配置、或对产物正确性要求较高的成员，也适合希望改动在提交前就确认无误的谨慎型贡献者。按[环境搭建](start/)装好锁定版本的 MkDocs 与 Material 主题后，用 `mkdocs serve` 实时预览、`mkdocs build --strict` 提交前自检，反馈最快、结果最确定，构建版本与线上严格一致。代价是需要先花一点时间把环境搭起来——这正是云端方案想替轻度贡献者省掉的部分。

相比旧的纯本地自构建模式，新流水线**大幅降低了贡献门槛**：省去本地安装依赖的繁琐操作、节省贡献者自己的本地算力（一次全站构建约 850 秒），也降低新手的上手学习成本——不必先学会一整套工具链，才能改一个错别字。

> **重要提示**：本系统为预发布版本，尚未稳定，需长期反复测试校验，不保证构建结果完全可靠，优先推荐本地构建；你也可以自行修改流水线配置进行测试。

完整说明见 [云端 CI 自动构建流水线](ci-build/)；若你连 PR 流程都想省掉，还可走[投稿区](inbox/)——只交付 Markdown 与索引文件，由维护者顺带装配构建。

## <img src="../ext/svg/icon-path.svg" alt="" width="22" height="22"> 学习路径建议

本板块按参与方向分两条路径，可先走「文档共建」熟悉协作，再按需要进入「项目开发」：

<img src="../ext/svg/learning-path.svg" alt="开发者文档学习路径：文档共建路线与项目开发路线，含配图技能" width="880">

1. 第一次参与文档共建：按顺序读完 **环境搭建** 和 **Markdown 写作规范**，即可开始写文档
2. 写完之后：按 **提交与上线流程** 提交，等待审核合并
3. 想帮社区调整站点结构（加栏目、改导航）：再看 **导航与站点配置**
4. 要开发并发布一个软件包：看 **GitHub 开发与软件包发布流程**

需要为文档配图时，可进一步阅读 [SVG 图标绘制与创作](svg-guide/) 与 [流程图开发与创作](flowchart-guide/)。

## <img src="../ext/svg/icon-terminal.svg" alt="" width="22" height="22"> 快速备忘

```bash
mkdocs serve      # 本地预览，保存即刷新
mkdocs build      # 构建静态产物到 site/
```

遇到问题先查[关于本站](../about/)的常见说明，仍无法解决可在 [GitHub 仓库](https://github.com/eoccc/eoccc.github.io)提 Issue。
