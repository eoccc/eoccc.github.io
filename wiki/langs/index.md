# 编程语言与数据格式

Mindustry 的模组、数据补丁与内容定义大量使用 **JSON** 及其超集 **HJSON** 作为配置载体。理解这两种格式，是读懂模组配置文件、编写数据补丁的前提。

本分支讲解这两种格式的语法结构、特性与相互关系。

## 为什么需要了解它们

Mindustry 的内容系统（方块、物品、单位、武器等）本质上是**结构化的数据**。游戏在加载模组时，会解析这些文本文件并据此构造对象。因此：

- 读得懂格式，才能看懂别人写的模组
- 写对格式，你的配置才会被正确解析
- 理解两者的差异，才能在「严格」与「易写」之间做取舍

## 两者的关系

一句话概括：**HJSON 是 JSON 的超集**。

<img src="assets/json-superset.svg" alt="JSON 与 HJSON 的集合关系：HJSON 是 JSON 的超集，合法 JSON 同时是合法 HJSON">

这意味着：

- 任何**合法的 JSON**，都是合法的 HJSON——可以直接被 HJSON 解析器读取
- HJSON 额外允许一些 JSON 不允许的写法（如注释、无引号键名、省略逗号）
- 反过来不成立：用了 HJSON 特有语法的文件，**不是**合法 JSON

## 格式选择速查

| 你的情况 | 建议格式 |
|---|---|
| 手写配置、想加注释说明 | HJSON |
| 程序生成、需要格式唯一 | JSON |
| 要交给只认标准 JSON 的工具 | JSON |
| 从已有 JSON 改造、想逐步加注释 | HJSON（原文件直接可用） |
| 团队协作 | 统一其一，避免混用 |
