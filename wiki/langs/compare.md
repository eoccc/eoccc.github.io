# JSON 与 HJSON 对比

本页把 [JSON](json/) 与 [HJSON](hjson/) 的差异汇总成速查表，并给出选用与转换建议。

## 集合关系

<img src="assets/json-superset.svg" alt="JSON 与 HJSON 的集合关系：JSON 是 HJSON 的子集，合法 JSON 同时是合法 HJSON">

**JSON ⊂ HJSON**。任何合法 JSON 都是合法 HJSON；反之不成立。

## 语法差异速查

| 特性 | JSON | HJSON |
|---|---|---|
| 键名引号 | **必须**用双引号 | 可省略 |
| 字符串引号 | 只能双引号 `"` | 双引号或单引号 `'` 均可 |
| 分隔逗号 | **必须**，且不能尾随 | 可省略，以换行分隔 |
| 注释 | **不支持** | 支持 `//`、`#`、`/* */` |
| 多行字符串 | 不支持（只能 `\n` 拼接） | 支持三引号 `'''` |
| 尾随逗号 | 报错 | 允许 |
| 数据类型 | 字符串/数字/布尔/null/对象/数组 | 与 JSON 相同 |
| 格式唯一性 | 唯一 | 同一份数据可有多种写法 |
| 解析器要求 | 任意 JSON 解析器 | 需支持 HJSON |

## 同一份数据的两种写法

**JSON**

```json
{
  "name": "duo",
  "health": 260,
  "requirements": [
    { "item": "copper", "amount": 35 }
  ]
}
```

**HJSON（等价）**

```hjson
{
  // 基础信息
  name: duo
  health: 260
  requirements: [
    { item: copper, amount: 35 }
  ]
}
```

解析后得到**完全相同**的数据。

## 选用建议

| 场景 | 建议 | 原因 |
|---|---|---|
| 人工编写、需要注释说明 | HJSON | 可写注释，键名与逗号可省，书写负担低 |
| 程序生成 / 机器读写 | JSON | 格式唯一，解析简单，工具链通用 |
| 需被只支持 JSON 的工具处理 | JSON | HJSON 特有语法会导致解析失败 |
| 从现有 JSON 配置改造 | HJSON | 零成本，原文件不改也能解析 |
| 团队协作 | 统一其一 | 避免混用造成风格不一致 |

## 转换方式

**JSON → HJSON：零成本**

合法 JSON 本身就是合法 HJSON，无需任何改写即可直接使用。想加注释或去掉引号时再逐步调整。

**HJSON → JSON：需要规范化**

需去掉 HJSON 特有语法：

- 删除全部注释
- 给所有键名补上双引号
- 补齐缺失的逗号，并移除尾随逗号
- 把三引号多行字符串改写为 `\n` 转义形式

可用任意 HJSON/JSON 互转工具完成，也可手动处理。

## 常见坑

**1. 把 HJSON 当 JSON 用**

用了注释或无引号键名的文件，交给严格 JSON 解析器会直接报错。使用前请确认目标环境支持哪种格式。

**2. 以为 JSON 里能写注释**

JSON 规范中**没有**注释。在 `.json` 文件里写 `//` 会导致解析失败——这是最常见的误用。

**3. 尾随逗号**

JSON 中最后一个元素后的逗号会报错；HJSON 中允许。从 HJSON 手改回 JSON 时容易漏掉。

**4. 缩进影响**

两种格式中，缩进都**不影响**解析结果，只影响可读性。但 HJSON 中省略逗号时，**换行**是有效的分隔符，此时不能把两个键值对挤在同一行。

## 逐项对照示例

同一份配置，两种写法并排看更直观。

**键名引号**

```text
JSON : { "health": 150 }
HJSON: { health: 150 }
```

**注释**

```text
JSON : 不支持，写了会报错
HJSON: // 单行    # 单行    /* 多行 */
```

**分隔逗号**

```text
JSON : { "a": 1, "b": 2 }      // 必须有逗号，末尾不能有
HJSON: { a: 1                  // 换行即可分隔
         b: 2 }
```

**多行字符串**

```text
JSON : "desc": "第一行\n第二行"
HJSON: desc: '''
        第一行
        第二行
      '''
```

## 选择决策流程

按顺序自问，命中即定：

1. 文件由**程序生成**吗？→ 是则用 **JSON**（格式唯一、便于比对）
2. 需要交给**只支持标准 JSON** 的工具吗？→ 是则用 **JSON**
3. 需要**写注释**说明字段用途吗？→ 是则用 **HJSON**
4. 配置较长、由人维护、追求可读性吗？→ 是则用 **HJSON**
5. 以上都不适用 → 沿用项目既有约定

## 一致性建议

无论选哪种，团队内应保持一致：

- 同一目录下不要混用两种扩展名
- 若从 JSON 迁移到 HJSON，建议一次性整体迁移，而非逐个文件
- 提交前用对应工具校验，避免把语法错误带进仓库
